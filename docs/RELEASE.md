# 컴파일 배포와 실행 범위

공개 `EESIZ/dashi`는 Linux x86_64·CPython 3.12용 컴파일 배포 저장소다. 이에 대응하는 원본·빌드·테스트는 비공개 `EESIZ/dashi_naked`에서 관리한다. 이번 배포는 로컬 통제 작성 경로를 GitHub 배포본에 포함하는 변경이며, 공개 Cloudflare 검사 서비스는 변경하지 않는다.

## 배포 구성

- `skills/dashi/scripts/dashi.py`: 최소 로컬 MCP 부트스트랩. 기존 검사·참고 도구 15개에 `compose`를 더한 16개 도구를 제공한다.
- `skills/dashi/scripts/compose.py`: 최소 CLI 부트스트랩. `--input`과 선택적인 `--output`만 받는다.
- `skills/dashi/scripts/*.so`: 기존 검사·참고 도구의 컴파일 구현.
- `skills/dashi/guard/`: 통제 실행기·호스트의 Cython 확장, 고정 검사 코드의 컴파일 저장부, 필요한 규칙·카드, 빌드 지문.
- `skills/dashi/SKILL.md`, `references/runtime.md`: 작성 시 반드시 준수할 호출·실패·전달 규약.
- `docs/ENFORCEMENT.md`: 사람과 AI 유지보수자 모두에게 적용되는 설계 계약.

고정 검사 코드는 작업마다 분리된 모듈 상태를 유지하도록 CPython 코드 객체를 Cython 저장부에 포함한다. 통제 실행기와 호스트는 Cython 확장 모듈이다. `guard/`에는 Python 원본·독립 `.pyc`·생성 C를 배포하지 않는다. 컴파일은 배포 방식이며, 분석이나 원본 복원을 불가능하게 만드는 보안 보장이 아니다.

수집한 수필 전체 원문과 원문 말뭉치·SQLite는 바이너리에도 숨겨 넣지 않는다. `essay_example`은 예문 자료 미배포 상태를 반환하며 통제 작성에서는 사용하지 않는다. `lit_methods`의 방법 카드와 배포에 필요한 기존 공개 자료는 [별도 출처·권리 고지](../NOTICE.md)를 따른다.

## 설치와 연결

[README의 설치 명령](../README.md#로컬-설치)을 따른다. `install.sh`는 `uv`로 Python 3.12 가상 환경을 만들고 고정된 의존성을 설치한 뒤 MCP 등록 명령을 안내한다. 사용자의 Claude 계정을 설치하거나 로그인하지 않는다. 통제 작성은 별도로 설치하고 인증한 Claude CLI가 호스트의 `PATH`에 있어야 하며, `claude-opus-5-5` 사용 권한이 필요하다.

MCP 등록의 실행 파일은 스킬 디렉터리의 `.venv/bin/python`, 인자는 `scripts/dashi.py`의 절대 경로다. 명령줄 작성은 같은 Python으로 `scripts/compose.py --input task.json --output approved.txt`를 실행한다. 예전 대화가 도구 목록을 보관하는 경우 MCP를 다시 연결한다. 원격과 로컬 MCP를 함께 쓰면 등록 이름을 구분한다.

`compose`를 외부 공개 HTTP 서비스에 그대로 연결하지 않는다. 모델 호출은 설치한 사용자의 인증과 사용량을 이용한다. 공개 원격 서비스의 기존 13개 도구와 이 로컬 작성 경로를 혼동하지 않는다.

## 업데이트와 복원

1. 실행 중인 설치를 직접 덮어쓰지 말고 새 커밋을 별도 디렉터리에 준비한다. 이전 Git 커밋과 스킬·MCP 등록 경로를 기록한다.
2. 새 위치에서 설치하고 검사 도구 목록, 정보 부족 시 본문 비공개, 실제 작성 성공 시 정확한 출력 전달을 확인한다. 기존 승인 결과를 임의로 다시 고치지 않는다.
3. 검증을 마친 뒤 스킬 링크와 MCP 등록을 새 경로로 전환하고 다시 연결한다. 가상 환경을 포함한 디렉터리 자체를 옮겼다면 가상 환경을 새 위치에서 다시 만든다.
4. 문제가 생기면 기록한 이전 릴리스와 등록으로 되돌린다. 통제 작성 도입 이전 버전으로 복원했다면 그 버전에 현재의 강제력이 있다고 주장하지 않는다.

## 배포 승인에 필요한 확인

[설계 준수 계약](ENFORCEMENT.md)을 먼저 읽는다. 대응 소스와 실제 컴파일 산출물의 지문, 실제 검사 결과의 일치, 정상·실패 출력 경계, 허용하지 않은 인자·가짜 승인 차단, 별도 위치의 깨끗한 설치를 확인한다. 작성 행동·모델·프롬프트·규칙이 달라지면 고정 과제의 실제 모델 실행과 블라인드 품질 평가도 다시 수행한다. 공개 파일 목록에 비공개 구현·생성 C·원문·자격 증명·호스트 경로가 없는지 확인한다.

개발 단계의 16회 비교는 기존 방식과 통제 방식 각각 8/8 완료, 토큰 57.99% 감소, 자연스러움 평균 각각 3.875/5, 실행시간 3.69% 증가였다. 이는 고정 합성 과제의 역사적 측정이다. 현재 바이너리 검증과 별개로 보존하며, 모든 입력의 품질 동등성·절감률이나 실행시간 단축으로 일반화하지 않는다.

최종 승인 기록에는 실제 수행한 결과만 남긴다. 수집 원문과 인증 정보는 포함하지 않는다.

## 2026-11-06 컴파일 배포 검증

- 소스 회귀 190개, 컴파일 경계·원본 동등성 17개, 네이티브 핵심 회귀 97개, 기존 검사·법률 통합 7개를 통과했다. 같은 회귀 항목을 소스와 바이너리에서 실행한 수를 고유 테스트 수로 합산하지 않는다.
- 별도 경로에서 install.sh로 새 환경을 설치했다. 실제 MCP 통신의 확인 항목 10개와 도구 호출 7회가 통과했다. 도구 16개, 문학 카드 20개, 법률 검사·예문, 미포함 원문 안내, 모호한 입력 시 본문 비공개, 임의 모델 인자 거부를 확인했다.
- 최초 실제 컴파일 작성은 3/4 완료했고 수필 1건은 별도 품질 검토로 차단됐다. 이후 같은 고정 과제의 소스/컴파일 비교를 각 1회씩, 재시도 없이 수행했다. 소스는 3/4, 컴파일은 4/4 완료했고 소스 수필 1건이 같은 사유로 차단됐다. 차단을 정상 작성 완료로 세지 않는다.
- 전달된 합성 결과 10개를 조건을 가리고 독립 평가했다. 모두 기준을 통과했다. 후속 비교의 컴파일 결과 4개는 자연스러움 평균 4.0/5, 소스 결과 3개는 3.67/5였다. 최초 컴파일 결과 3개도 4.0/5였다. 작은 표본에서 품질 저하를 발견하지 않았다는 범위이며 품질 향상·보편적 동등성·모든 요청의 완료를 증명하지 않는다.
- 공개 산출물은 네이티브 모듈 31개와 최소 Python 부트스트랩 4개다. 소스/산출물 지문, 고정 규칙·카드, 원문 모음 제외, 개발자 경로·자격 증명 패턴 제외를 확인했다. 원본 통제 작성 행동·모델·프롬프트는 유지했다.

공개 원격 서비스는 이번에 변경하지 않았다. 이 서버에서 원격 도구 목록 조회는 HTTP 403으로 확인되지 않았으며, 문서의 원격 13개 범위는 변경하지 않은 배포 소스·설정에 근거한다. 로컬 16개 도구는 새 설치에서 실제 확인했다. 이번 검증은 토큰 절감률을 새로 측정하지 않았다.

비공개 체크아웃만 사용해 빈 디렉터리에서 전체 배포본을 재생성하는 `tools/build_release.py`도 두 컴파일과 두 승인 검사를 끝까지 통과했다. 빌드 후 설치 위치에 독립적인 설계 계약 링크와 기존 법률 안내 문서 두 곳을 양쪽 저장소에 맞추고 빈 폴더 표시 파일을 정리했다. 문서 동기화 후 재현본과 공개 스킬의 전체 파일이 바이트까지 일치한다. 실행 코드·검사 자료·소스 지문은 그대로다.
