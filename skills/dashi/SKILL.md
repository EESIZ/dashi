# dashi

도구는 MCP 서버 `dashi`에 있다(설치는 install.sh). 규칙 본문과 기준 분포가 서버 안에 들어 있으므로 도구가 돌려주는 설명을 그대로 따르면 된다.

## 순서

0. **입장** — 쓰기 전에 관계(당사자/우호/비판/심판)·독자·의도 한 동사·안 쓸 말 둘을 정한다. 요청에 없으면 장르 화자 안에서 고르고 사용자에게 보인다. 사람이 쓴 원문을 다듬을 때는 원문의 어미에서 뽑는다.
1. **장르** — `classify(text)` 후보를 요청과 맞춰 정하고, 장르는 묶음 이름으로 넘긴다: `논설`(사설·칼럼·기사·연설·논술), `법률문서`(판결문·결정문·소송서류·계약서). 행정문서·문학은 준비 중이라 가장 가까운 묶음을 쓰고 사용자에게 말한다. 옛 이름(사설·판결문)도 받아 준다.
2. **뼈대** — `skeleton(genre)`가 주는 문장 기능 뼈대와 `rules`를 그대로 따른다.
3. **채우기** — 첫 통과는 사실만 볼 순서대로, 둘째 통과에서 뼈대가 정한 칸만 판단·당위로 채운다. 앞에 없는 근거로 판단하지 않는다.
4. **문장 게이트** — `sentence_gate(text, genre)`. FAIL이면 `regen_prompt(text, genre)`가 주는 프롬프트대로 지목된 문장과 필요한 앞뒤 문장을 고치고 본문 전체를 다시 검사한다. 사실을 더하지 않는다.
   - **재검사 횟수로 끝내지 않는다.** 사용자에게 줄 최종 본문으로 `sentence_gate`를 실행해 실제 `verdict: PASS`를 받을 때까지 계속한다.
   - 문장별 위반이 0이고 R5(글 단위)만 남아도 계속한다. 어느 지표가 어느 쪽으로 벗어났는지 보고 문장 합치기·나누기·연결어미 조정 중에서 고르고, 같은 수정으로 같은 위반이 되풀이되면 교정 방식을 바꾼다.
   - 원문의 사실, 사건 순서, 직접 인용의 문구와 순서를 지킨다. 소설처럼 짧은 대화가 중요한 글은 인용문을 고치지 말고 주변 서술을 조정한다. 통과를 위해 기준이나 검사 대상 본문을 바꾸지 않는다.
   - `PASS`를 받은 본문을 그대로 전달한다. 전달 전에 한 글자라도 고쳤으면 다시 검사한다. 도구 오류로 판정을 확인할 수 없거나 사용자가 중단을 요청하면 마지막 판정 상태(남은 문장·지표)를 정확히 알린다.
5. **검사** — `check(text, genre)`로 표면 지표를 장르 분포와 대조한다. 경고는 단어가 아니라 동작을 가리킨다. 이 경고는 참고로 따로 보고하며 `sentence_gate` 통과와 구분한다.
6. **기록** — 사용자가 고쳐 준 표현은 `correction(before, after, reason)`에 저장하고, 쓰기 전에 `correction(query=…)`로 찾아본다.

## 한계

- 기준 분포는 사설 장르 사람 글에서 계산한 것이다. 다른 장르는 가장 가까운 것으로 쓰고 사용자에게 말한다.
- 게이트는 문장 안과 호흡을 잡는다. 입장 자체는 글 밖의 정보라 어떤 도구도 대신 채우지 못한다.
