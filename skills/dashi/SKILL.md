# dashi

AI 한국어의 티는 문장보다 앞에서 생긴다. 누가 말하는지가 없고, 보여 주기 전에 판정하며, 글쓴이가 손을 쓰는 언어로 생각한다. 그래서 이 스킬은 다 쓴 글을 고치기보다 쓰는 순서를 바꾸는데, 그 순서는 장르마다 다르다. 판결문을 쓰는 법과 사설을 쓰는 법은 같은 절차의 변형이 아니라 다른 절차다. 도구는 MCP 서버 `dashi`에 있으며, 원격 주소로 붙이거나 install.sh로 설치해 등록한다(README 참고).

## 공통층

장르에 상관없이 지키는 것은 둘뿐이다.

1. **경로 정하기.** 글쓰기·다듬기 요청이 오면 맨 먼저 `route`를 부른다. 돌아온 읽기 양식을 요청과 원문에서 채우고 값마다 근거 구절을 인용해 다시 부른다. `ask`가 오면 그 말을 그대로 사용자에게 묻는다. `ready`면 돌려받은 path 경로로 가고, `no_path`나 `handoff`면 그 사실을 알리고 멈춘다. `classify(text)`는 원문의 장르 후보를 보는 참고값이며, 경로는 route가 정한다. 정한 장르는 사용자에게 보이고, 조용히 정하지 않는다.
2. **사실 불변.** 어느 경로든 원문이나 자료에 없는 사실·숫자·인용·판례를 더하지 않는다. 없는 것은 "[확인 필요]"로 표시한다. 고칠 때는 문장을 합치고 지우고 순서를 바꾸는 것만 한다.

도구는 읽기 전용이다. 요청으로 받은 글은 그 요청의 분석에만 쓰고, 어떤 도구도 원문·교정문·꼬리표·검사 결과를 저장하거나 기준 분포를 바꾸지 않는다. 사용자가 고쳐 준 표현은 대화 안에서만 쓰고, 말뭉치와 교정 일지에 남기는 일은 운영자가 명령줄로 한다.

## 경로

| 장르 | route path | 절차 |
|---|---|---|
| 논설·평론, 연설문, 논술, 주장문·토론문 | `opinion` → [opinion/SKILL.md](opinion/SKILL.md) | 입장표 → 전개 방식(E·A·O) → `skeleton` → 채우기 → `sentence_gate` 루프 → `check` |
| 판결문·결정문, 소장·준비서면, 의견서 | `legal` → [legal/SKILL.md](legal/SKILL.md) (MEKA 곽윤직) | 전개 방식(P·O) → 작성 → 판례 근거 게이트 → `legal_style` 측정·퇴고 → 형식 게이트 |
| 공문(시행문·기안문) | `admin_rules` (편람 규정) | 「행정업무운영 편람」 규정대로 쓰고 `admin_check(text, form='공문')`으로 표기·어문을 검사한다. 지목된 자리만 고친다 |
| 기사·보도자료, 공고·공지·안내문 | 없음 | 쓰기 경로가 없다. 사용자가 검사를 원하면 `admin_check`(form='보도자료' 또는 '공문')로 표기만 본다 |
| 법령·규정(조문) | 없음 | 쓰기 경로가 없다. 사용자가 이름을 댈 때만 `admin_check(form='조문')`(법제처 입안 기준)으로 검사한다 |
| 보고서·매뉴얼·논문 | 없음 | 행정문서 분포 눈금만 있다. 요청이 오면 경로가 없다고 말하고, 사용자가 원할 때만 논설 경로의 문장 게이트를 행정문서 눈금으로 돌린다 |
| 계약서, 건의·요청문, 자기소개서, 업무 이메일, 의례 글, 편지 | 없음 | 경로가 없다고 알리고 멈춘다 |
| 문학(시·소설·희곡·수필 등) | 없음 | 분포도 아직 없다는 점까지 같다 |

경로의 절차와 전개 방식은 `opinion_guide`·`legal_guide`가 돌려준다. 한 경로의 도구를 다른 경로의 장르에 넣으면 안내만 돌아온다.

## 한계

- 분포는 구워 둔 기준(사람 글)만큼만 믿을 수 있다. 장르별 편수와 꼬리표 기준 유무는 `stats`로 본다. 기준이 없는 장르는 도구가 그 상태를 돌려주고, 사용자 글로 기준을 채우지 않는다.
- 입장 자체는 글 밖의 정보라 어떤 도구도 대신 채우지 못한다.
