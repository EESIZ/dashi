# 문장 꼬리표 지침

입력 파일의 각 줄은 `ID<TAB>문장`이고 `### 문서id` 줄이 문서 경계이며, 모든 문장에 아래 다섯 꼬리표(기능·어미의 주인·주어 유형·위치·메모)를 하나씩 달되 문장 자체를 고치거나 빼지 않는다.

## fn (문장 기능) — 하나만
- F 사실: 일어난 일·수치·제도 내용을 평가 서술어 없이 서술한 문장으로, "2025년까지 10년간 수익률은 2.78%에 그쳤다."가 그 예다.
- R 전문: 남의 말을 "~라고 한다", "~고 말했다", "~고 밝혔다", "~에 따르면"처럼 간접 전달한 문장이다.
- Q 인용: 직접 인용이 중심이다.
- I 해석: 글쓴이의 풀이지만 "~로 보인다", "~로 읽힌다", "~로 풀이된다", "~는 셈이다", "~는 뜻이다", "~기 때문일 것이다", "가능성이 크다"처럼 보이는 것으로 표현한 문장이다.
- J 판단: "궁색하다", "옳다", "무책임한 결정이다", "설득력이 없다", "수긍하기 어렵다", "문제다"나 수사의문("~란 말인가")처럼 글쓴이 목소리로 평가·단정한 문장이다.
- D 당위: "~해야 한다", "~해야 할 것이다", "~바란다", "~안 된다", "~필요가 있다"로 요구하거나 촉구하는 문장이다.
- C 조건/가정: "~면 ~다" 형태로 가정 위에 결과를 놓는 문장이 중심일 때 달되, 끝이 당위면 D로, 평가면 J로 단다.

판단 기준은 문장의 **마지막 서술어**이므로, 사실을 아무리 길게 쓰더라도 끝이 "무책임한 결정이다"면 J로 단다.

## own (어미의 주인) — 하나만
- self: 글쓴이가 자기 이름으로 단정 ("~다", "~이다", "~어렵다")
- other: 남의 말로 ("~라고 한다", "~밝혔다", "~따르면")
- seem: 보이는 것으로 ("~보인다", "~읽힌다", "~셈이다", "~것이다"(추정), "~수밖에 없다", "~아닐 수 없다")
- norm: 당위로 ("~해야 한다", "~바란다")
- none: 순수 사실 서술 ("~했다", "~이다"가 사실 기술일 때)

## subj (주어 유형) — 하나만
- P 사람·기관 (정부, 대통령, 청년들, 국회, 이 원장)
- E 사건·사실·제도·수치 (과세, 수익률, 협정, 이번 결정)
- A 추상 개념 (경쟁력, 신뢰, 원칙, 방향, 성패, 책임)
- 0 주어 생략

## pos (문단 안 위치) — 자동이지만 확인용: head(문단 첫 문장) / mid / tail(문단 끝 문장). 한 문장짜리 문단은 head.

## 출력
JSON 배열 하나이고 각 원소는 {"id": "...", "fn": "F|R|Q|I|J|D|C", "own": "self|other|seem|norm|none", "subj": "P|E|A|0", "note": "애매하면 한 줄, 아니면 빈 문자열"}
입력에 있는 모든 ID가 빠짐없이 들어가야 하며, 다른 설명은 쓰지 말고 지정된 파일에 JSON만 저장한다.
